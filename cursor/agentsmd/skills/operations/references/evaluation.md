# Bounded model and workflow evaluation

Use for an explicitly requested evaluation or an authorized experiment whose
question requires it. This is not an automatic AgentsMD release gate.

Define the decision, representative tasks, permitted tools and side effects,
candidate identities, rubric, resource limits, and stopping condition. Freeze
these before comparing outcomes. Give workers the real task requirements; keep
grading labels blind when appropriate to an experimental comparison, not as a
reason to hide required success criteria from an implementation worker.

Use independent cases or held-out checks where prompt overfitting could create
false confidence. Keep environments and available information comparable.
Record model, effort, prompt/Skill revision, tools, artifacts, failures, and
grading evidence. Separate repeated runs from independent tasks, and execution
cost from quality. A tiny convenient sample cannot establish general superiority.

Inspect actual artifacts and execution evidence. Grade against observable
criteria with consistent adjudication. Record inter-reviewer disagreement and
investigate the underlying evidence instead of choosing a preferred voice.
Preserve privacy and scope when examples come from real work.

Report the supported conclusion, sample boundary, confounders, and what would
change the decision. Follow explicit model/effort constraints. Do not buy credits,
publish data, schedule recurring runs, or claim behavioral Live Verification from
a synthetic exercise without the corresponding authority and evidence.
