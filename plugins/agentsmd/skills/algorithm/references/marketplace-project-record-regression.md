# Marketplace Project Record regression

This is the real design regression that motivated the model-invoked Algorithm
Skill. It is not a synthetic evaluation or a disposable behavioral project.

## Evidence sources

- [`toolboxmd/agentsmd#32`](https://github.com/toolboxmd/agentsmd/issues/32)
  records the first-draft failure and the corrected pass.
- [`toolboxmd/marketplace#6`](https://github.com/toolboxmd/marketplace/issues/6)
  preserves the corrected Project Record contract and its released result.

## First draft

The first Project Record draft jumped directly to a comprehensive schema, an
accepted-record snapshot, a provenance lock, and a three-release design. The
agent had the complete Algorithm prose in context but did not make questioning,
deletion, or simplification observable before proposing that design.

## Corrected draft

After the user challenged whether the Algorithm had been applied, the corrected
pass deleted the separate snapshot, separate lock, registry state, duplicated
release and manifest facts, and automatic reconciliation. The surviving design
became a minimal neutral index over existing released sources.

The published Marketplace Issue confirms those corrections: the Project Record
points at existing released fact owners, `catalog.json` remains the only
accepted Marketplace state, and automatic listeners wait until the manual loop
is proven stable and recurring.

## Regression expectation

For material design work, the agent must leave observable evidence of the
questioned requirement, deletion decisions, and simplified survivor before it
accelerates delivery or automates a loop. A direct microfix remains direct.
