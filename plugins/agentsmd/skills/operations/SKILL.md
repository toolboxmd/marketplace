# Operations

The core `AGENTS.md` owns alignment, judgment, task routing and authority.
These references own operational detail. Apply existing authority and local
Project Direction exceptions; this Skill grants no new permission.

Resolve this Skill through installed discovery or the canonical AgentsMD source
behind the global instruction symlink as described in the core. Keep the core
and these references on one coherent compatible source revision. Resolve every
relative link from this actual Skill file, not the target project's cwd.
A missing required reference blocks only the dependent action; report its
resolved path. Reuse unchanged reference contents already in context.

Read only the module whose trigger applies, including linked prerequisites:

| Before this action | Owning module |
| --- | --- |
| Editing tracked files, selecting or reusing a task workspace | [Implementation](references/implementation.md) |
| Delegating, coordinating dependencies, continuing from a handoff | [Orchestration](references/orchestration.md) |
| Running or reusing proof, reviewing, claiming readiness or Live Verification | [Verification](references/verification.md) |
| PR delivery, merge, release, artifact promotion or website classification | [Delivery](references/delivery.md) |
| Closing a terminal outcome or removing task-owned transient resources | [Finalization](references/finalization.md) |
| Resolving an unverified required repository capability, settings change or capability drift | [Repository setup](references/repository-setup.md) |
| Repairing detected drift, mutating legacy resources or recovering cleanup | [Reconciliation](references/reconciliation.md) |

Load `delivery-profile` when a Project declares `.toolboxmd/delivery.json` or
its delivery configuration is being decided. Use `version-control` for version
mechanics, `project-direction` for direction repair, and `algorithm` for
material design. Do not load unrelated modules for read-only explanations.
